# Метрики тестирования

Все числа получены из артефактов репозитория, способ пересчёта - в разделе 7. **Ограничение:** живой прогон
стенда не выполнялся (Docker недоступен), поэтому статусы получены **разбором кода**, а не наблюдением за
системой.

## 1. Объём

- Тест-кейсы: 15 API (`TC-API-01...15`) и 12 UI (`TC-UI-01...12`), всего 27.
- Пункты чек-листов: 68 API, 72 веб-сервис, 45 доступность, всего 185.
- Дефекты: 15 API и 13 WEB, всего 28.
- Newman-коллекция: 94 запроса, 386 проверок `pm.test`, из них 31 помечен `[KNOWN BUG]`.
- SQL-проверки: 25 по трём базам.

## 2. Серьёзность и приоритет

Severity: у API 3 Critical, 9 Major, 3 Minor; у веб-сервиса Critical нет, 6 Major и 7 Minor. Priority: у API 9
High, 5 Medium, 1 Low; у веб-сервиса 4 High, 7 Medium, 2 Low.

Три Critical лежат в трёх разных слоях и объединяются одной причиной - **граница доверия нигде не проверяется на
входе**: [API-01](../bug-reports/critical.md#api-01-открытый-прокси-для-файлов-ssrf) - открытый прокси во
frontend, [API-02](../bug-reports/critical.md#api-02-анонимный-доступ-к-персональным-данным-и-файлам) -
публичное правило маршрута в gateway, [API-15](../bug-reports/critical.md#api-15-публичная-регистрация-позволяет-выбрать-роль-учёного)
- непроверенное `role` в `user-service`. У веб-сервиса Critical нет, но 6 из 13
дефектов - Major, и почти все ломают основной сценарий: нельзя войти, создать проект, отправить отчёт.

## 3. Плотность дефектов по чек-листам

- API - 25 дефектов на 68 проверок, **37 %**.
- Веб-сервис - 17 на 72, **24 %**. Доступность - 19 на 45, **42 %**. Всего 61 на 185, 33 %.

Доступность - самое слабое место: все 19 находок сводятся к одной причине, видимой в коде, - UI написан вручную,
без библиотеки компонентов и без проработанной семантики (`<div>` вместо `<button>`, `<h3>` без `<h2>` в секции,
нет `aria-*`). Точечно в семи компонентах дешевле, чем переписывать интерфейс.

## 4. Дефекты по сервисам

Дефект может затрагивать несколько сервисов, поэтому сумма больше 15.

- `user-service` - 5: API-04, API-05, API-10, API-11, API-15.
- `project-service` - 4: API-07, API-08, API-14, API-15.
- `observation-service` - 4: API-07, API-09, API-13, API-15.
- `gateway` - 2: API-02, API-04. Frontend (Next.js) - 13: все WEB-01...13.

Три дефекта затрагивают сразу два сервиса: **API-04**, **API-07** (project-service + observation-service - нет
внешнего ключа при удалении проекта) и **API-15** (все три сервиса). Именно межсервисные дают наибольший прирост
времени на устранение: они требуют согласования изменений между репозиториями.

## 5. Автоматизация

- API-дефекты с автотестом: **12 из 15** (80 %). Без автотеста - **3**: API-01, API-04, API-05.
- WEB-дефекты с автотестом: **0 из 13**. Сценариев `[KNOWN BUG]` на закрытый дефект: 31 / 12 ~ 2,6.

Причина у трёх API-дефектов одна - нужен шаг, которого нет в Newman: **API-01** живёт в
`frontend/app/api/file-proxy/route.ts`, а Newman ходит на gateway `:8080` и маршрута не видит;
**API-04** - лимита частоты в коде нет; **API-05** требует понизить роль в `users_db` после выдачи
токена, то есть доступа к БД между шагами (`psql`, инструкция в [stand/README.md](../stand/README.md)).

**Почему web-дефекты не автоматизированы.** Newman работает по HTTP и не видит DOM, а все 13 WEB-дефектов
- это отрисовка, навигация, доступность и тексты: нужен Playwright или Cypress, а инфраструктуры
браузерных тестов в объект не входит. Поэтому они закрыты тест-кейсами `TC-UI-*` и ручным прогоном. Исключение -
**WEB-07**: его API-половина проверяется в папке `10 Contract`, но ошибку проглатывает компонент, то есть в
Newman она снова невидима.

## 6. Коды Newman

- `0` - все известные дефекты воспроизвелись, регрессий нет. **Ожидается на текущем коде.**
- `1` - регрессия или сценарий разошёлся с ожиданиями. Не ожидается.
- `2` - стенд недоступен, прогон недействителен целиком. На текущей базе не бывает.
- `3` - известный дефект перестал воспроизводиться, то есть его починили.

Набор из 386 проверок должен проходить **целиком**, иначе он перестаёт быть фиксированной точкой сравнения. Как
только дефект исправят, сценарий перестанет проходить, `api/summarize.py` вернёт `3`, и тест-кейс можно будет
закрыть.

## 7. Как пересчитать

```bash
python3 api/validate_collection.py   # 94 запроса, 386 проверок, 31 [KNOWN BUG], компиляция assert-скриптов
python3 api/test_summarize.py        # классификатор кодов 0 / 1 / 2 / 3
APP_DIR=/путь/к/gra python3 stand/validate_seed.py && bash -n stand/up.sh && bash -n api/newman.sh

# пункты и отметки дефектов в чек-листах -> 185 и 61
grep -chE '^\s*- \[( |x|!|-)\]' checklists/*.md | paste -sd+ | bc
grep -chE '^\s*- \[!\]' checklists/*.md | paste -sd+ | bc
# дефекты -> 15 и 13, тест-кейсы -> 27, SQL -> 25
grep -chE '^### API-[0-9]+\.' bug-reports/*.md | paste -sd+ | bc
grep -chE '^### WEB-[0-9]+\.' bug-reports/*.md | paste -sd+ | bc
grep -chE '^### TC-(API|UI)-[0-9]+' test-cases/*.md | paste -sd+ | bc
grep -ohE "^\\echo '\[[UPO][0-9]+[a-z]?" sql/0*.sql sql/1*.sql sql/2*.sql | sort -u | wc -l
```

Битая ссылка или расхождение чисел - дефект документации, а не опечатка.
