**Объект:** платформа citizen science - frontend (Next.js), gateway (Rust), 4 микросервиса (Rust),
3 изолированные БД (PostgreSQL), Redis-сессии, MinIO.
**Дата:** 13.06.2026. **Автор:** Орловский Андрей. **Артефакты:** `/mnt/c/prog/qa/gra`

## 1. Итог

**Дефектов 28** - 15 в API и 13 в web-сервисе. Из них **Critical 3**: API-01 (SSRF), API-02 (анонимный
доступ к персональным данным), API-15 (выбор роли учёного при регистрации). **Автоматизировано

Основной результат: **дефекты сконцентрированы на границах доверия** - между ролями, сервисами и
тремя изолированными базами: значение из клиентских данных, которому сервис затем доверяет без
перепроверки.

## 3. Ключевые дефекты

Три Critical разобраны в [bug-reports/critical.md](../bug-reports/critical.md): открытый прокси для
файлов (API-01), анонимный доступ к персональным данным (API-02), выбор роли учёного при публичной
регистрации (API-15). Они лежат в трёх разных слоях - frontend, gateway, `user-service` - и сводятся
к одной причине: значение из клиентских данных попадает в систему и тут же ей доверяется.

Из остальных 25 дефектов характер выборки задают пять: роль, зафиксированная в токене на 24 часа
(API-05); каскадное удаление ответов вместо мягкого (API-09); поддельный MIME-тип, сохранённый как
`image/png` (API-13); ошибки API, которые `frontend/lib/api/client.ts` проглатывает, и пользователь видит
"ничего не найдено" вместо `500` (WEB-07); дубликаты наблюдений без предупреждения (WEB-01).
Полный индекс с severity, priority и ссылками - [bug-reports/README.md](../bug-reports/README.md).

## 5. Как читать результат прогона

Сценарий с маркером `[KNOWN BUG]` **должен проходить на текущем коде**: он утверждает не "дефекта
нет", а "дефект воспроизводится ровно так, как описано в баг-репорте".

- **Дефект есть.** Фиксирует ошибочное поведение, поэтому проходит, код выхода `0`.
- **Дефект исправлен.** Утверждение перестаёт выполняться, сценарий падает, код `3`.
- **Затронут соседний код.** Падает неожиданно, код `1` - нужен разбор.
- **Стенд не поднялся или нет сети.** Падает как сетевая ошибка, код `2`.

**Ненулевой код - не "тесты сломались", а сигнал, что продукт изменился.** Код `3` - дефект
исправлен, кейс можно закрывать. Ожидаемый прогон на дефектной базе - `0`, все 386 проверок зелёные.

## 6. Ограничения

1. **Живой прогон не выполнялся.** Docker недоступен: WSL integration отключена (`The command
   'docker' could not be found in this WSL 2 distro`). Статически проверено: `bash -n` для скриптов,
   seed против схемы миграций, SQL через `sqlglot` - 26 операторов из 26.
2. **Статусы в кейсах и чек-листах получены разбором кода**, а не наблюдением: колонки "Фактический
   результат" оставлены под подтверждение живым прогоном.
3. **Покрытие кода не измерялось** - нет Rust-тулчейна для `cargo llvm-cov`.
4. **Web-дефекты не автоматизированы** - нужен Playwright или Cypress, инфраструктуры нет.
5. **SQL не исполнялся на живой PostgreSQL** - только разбор; возможны мелкие расхождения в тексте
   вывода, но не в логике.
6. **CORS и preflight проверены чтением кода** gateway: зависит от заголовков балансировщика, здесь
   не воспроизводятся.

Закрыть пункты 1-2: `./stand/up.sh backend`, затем `./api/newman.sh`, затем
`./stand/up.sh psql users_db < sql/00-users-db.sql` и аналогично для двух других баз.

## 7. Рекомендации по приоритету

1. **Закрыть три Critical до релиза:** три слоя, одна причина - общий фикс дешевле трёх патчей.
2. **Ввести внешние ключи между базами** (API-07, API-11): изоляция баз не отменяет ссылочную целостность.
3. **Не удалять комментарии каскадно** (API-09): мягкое удаление с пометкой "родитель удалён".
4. **Валидировать вход, а не только тип** (API-13, API-07): проверка по magic-байтам.
5. **Показать пользователю ошибку** (WEB-07): однострочное изменение с самым высоким эффектом.
6. **Внедрить Playwright:** 13 web-дефектов сейчас не ловятся автоматически.
7. **Добавить доступность в критерии приёмки:** не проходит 19 из 45 проверок - нужна библиотека.
